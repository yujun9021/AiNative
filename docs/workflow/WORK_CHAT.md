# 작업 채팅 규칙

작업 채팅은 총괄의 기술·아키텍처 승인과 개발환경 검증이 끝난 뒤 하나의 `AN-xxx`를 끝까지 수행한다.


## 순서

1. 총괄 전달문의 현재 단계와 작업 범위를 읽고 그 단계부터 시작한다.
2. `spec.md` 승인 후 `plan.md`를 작성한다.
3. intent의 범위 변경이 필요하면 구현하지 말고 총괄 채팅에 전달한다.
4. plan 승인 후에만 코드를 변경한다.
5. 검증 결과를 `evidence.md`에 기록하고 작업 상태를 `review`로 바꾼다.
6. 아래 사용자 인수 시나리오를 실행하고 결과를 기록한다.
7. 사용자 인수 후 작업 상태를 `done`으로 바꾸고 최종 커밋 1회로 남긴다.

## 사용자 인수

- `spec.md`의 인수 시나리오를 사용자가 직접 확인한다.
- 결과를 `evidence.md`의 사용자 인수 항목에 `통과`, `수정 필요`, 또는 `보류`로 기록한다.
- `수정 필요`이면 상태를 `building`으로 되돌리고 필요한 범위를 다시 승인받는다.
- `통과`일 때만 최종 커밋과 `done` 전환을 진행한다.

## 범위 변경

다른 기능이나 공통 구조에 영향을 주면 구현을 멈추고 사용자로 하여금 총괄 채팅에 전달하도록 한다.
총괄 결정 전에는 해당 범위의 코드와 문서를 수정하지 않는다.

```text
[총괄 전달 요청]
작업 ID: AN-xxx
현재 단계:
발견:
영향:
제안: 기존 작업에 포함 | 새 AN-xxx 생성
의존성:
중단 범위:
결정 필요:
```
