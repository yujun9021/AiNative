# 총괄 채팅 규칙

총괄 채팅은 제품 기능을 구현하지 않고, 프로젝트 기반 환경을 세팅·검증한 뒤 방향과 작업 흐름을 관리한다.

## 시작

1. `신규 프로젝트 인터뷰와 시작 조건`을 사용자 인터뷰로 충족한다.
2. 확정된 프로젝트 기준을 ROADMAP에 기록한다.
3. 명시적인 환경 세팅 승인을 받은 뒤 최소 개발환경을 세팅하고 실행을 확인한다.
4. 세팅 검증이 끝난 뒤 아래 작업 구성 작성 기준에 따라 작업을 나누고, ROADMAP의 `## 작업 구성` 표에
   `AN-xxx`, 결과, 구성 승인, 상태, 의존성, 인수 기준을 기록한다.
   작업 구성 표를 작성하면 사용자 승인 전에 작업 ID의 직렬·병렬 관계를 나타낸 의존성 흐름도를 함께 보여준다.
5. 사용자가 작업 구성과 순서를 승인하면 해당 행의 구성 승인을 `approved`로 바꾼다.
6. 승인됐고 의존성이 없는 첫 작업에만 `work/_template/intent.md`로 초기 intent를 만든다.
7. 사용자가 초기 intent를 확인하면 작업 채팅을 시작한다.

## 신규 프로젝트 인터뷰와 시작 조건

신규 프로젝트는 아래 항목을 사용자와 인터뷰해 구체화한다. 모든 항목을 확인하기 전에는
작업 구성이나 초기 `intent`를 확정하지 않는다.

- 대상 사용자와 해결할 문제가 확인됐다.
- 신규 프로젝트인지 기존 코드 변경인지 확인됐다.
- 기술스택과 아키텍처가 사용자 승인으로 확정됐다.
- 개발환경의 최소 실행 확인이 끝났다.
- 첫 버전의 필수 결과와 성공 기준이 확인됐다.
- 현재 범위와 제외 범위를 사용자가 확인했다.

조건을 확인하기 전에는 작업 ID와 초기 intent를 확정하지 않는다. 로그인 방식, 기술 스택,
제외 기능처럼 사용자가 정하지 않은 사항을 임의로 결정하지 않고 질문한다.
개발환경에는 런타임·패키지 관리자·실행 명령·필요한 설치와 권한을 기록한다.
프로젝트 초기 생성, 필수 의존성·구성, 빈 앱의 빌드·실행 확인까지 총괄의 개발환경 세팅으로 완료하며, 이를 `AN-xxx`로 등록하지 않고 작업 구성에는 사용자 기능 구현만 넣는다.
신규 프로젝트는 작업 채팅을 만들기 전에 총괄에서 환경 세팅 확인을 끝낸다.

## 작업 구성 작성 기준

- 먼저 핵심 사용자 흐름을 단계로 나누고 각 작업이 어느 흐름을 완성하는지 확인한다.
- 한 작업은 실제 사용자 흐름에서 독립적으로 인수할 수 있는 결과만 가진다.
- 앞 작업의 실제 결과·데이터·권한·화면 맥락 없이는 시작하거나 인수할 수 없으면 하나로 묶는다.
- 목업·임시 데이터로만 독립 실행할 수 있는 경우는 병렬 작업으로 인정하지 않는다.
- 공통 기반 이후 독립적으로 구현·인수할 수 있는 작업은 병렬 수행 가능하도록 나눈다.
- 병렬 작업의 결과가 만나는 지점은 별도의 통합 작업으로 둔다.
- 작업 수를 늘리기보다 가장 긴 의존성 사슬을 줄이는 구성을 우선한다.
- 하나의 긴 사용자 흐름이고 병렬 수행·독립 인수가 불가능하면 크기와 관계없이 하나의 작업으로 유지한다.
- 크기만으로 분할하지 않고, 독립적으로 인수할 수 있는 결과가 있을 때만 나눈다.
- 작업 구성과 순서를 사용자가 승인하기 전에는 개별 intent를 작성하지 않는다.
- 승인 전 구성 승인은 `pending`, 사용자 승인 후에는 해당 행을 `approved`로 바꾼다.
- 승인 전 구성안과 승인 후 작업 목록은 별도 표로 만들지 않고 `## 작업 구성` 표를 갱신한다.

각 행의 의미는 다음과 같다.

- `ID`: 작업 식별자. 승인 여부와는 별개다.
- `결과`: 작업이 끝났을 때 사용자가 확인할 결과.
- `구성 승인`: 작업 구성 자체에 대한 사용자 승인 상태.
- `상태`: 실제 작업 진행 상태.
- `의존성`: 먼저 완료되어야 하는 작업 ID.
- `인수 기준`: 작업 완료를 판단할 수 있는 관찰 가능한 조건.

## 관리

- 우선순위, 의존성, 작업 상태만 관리한다.
- 상세 요구사항·코드·테스트 로그는 작업 채팅에서 다룬다.
- 범위 변경 요청을 승인하거나 새 작업 ID를 만든다.
- 작업 채팅의 완료 보고를 확인하고 ROADMAP을 `done`으로 바꾼다.

## 작업 채팅 전달

```text
이 채팅은 AN-xxx 작업 채팅이다.
먼저 AGENTS.md, docs/workflow/WORK_CHAT.md,
docs/workflow/ROADMAP.md의 AN-xxx 행, 해당 작업 문서와
현재 변경 상태를 읽어라.
총괄에서 `intent.md` 사용자 승인이 완료됐다. intent 승인을 재요청하지 말고
`spec.md` 작성 단계부터 시작하라. 승인된 intent의 범위 변경이 필요하면 구현하지 말고
총괄 채팅에 전달하라.
```
