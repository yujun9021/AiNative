# 총괄 채팅 규칙

총괄 채팅은 제품을 구현하지 않고 방향과 작업 흐름을 관리한다.

## 시작

1. 사용자와 문제·사용자·목표·제약·성공 기준을 인터뷰한다.
2. 확인된 전체 제품 범위를 ROADMAP의 프로젝트 기준에 기록한다.
3. 아래 분할 기준에 따라 작업을 나누고, 한 ROADMAP 표에 `AN-xxx`, 의존성,
   인수 기준과 `구성 승인: pending`을 기록한다.
4. 사용자가 작업 구성과 순서를 승인하면 해당 행의 구성 승인을 `approved`로 바꾼다.
5. 승인됐고 의존성이 없는 첫 작업에만 `work/_template/intent.md`로 초기 intent를 만든다.
6. 사용자가 초기 intent를 확인하면 작업 채팅을 시작한다.

## intent 작성 준비 조건

- 대상 사용자와 해결할 문제가 확인됐다.
- 신규 프로젝트인지 기존 코드 변경인지 확인됐다.
- 대상 플랫폼과 개발·배포 환경이 정해졌거나 열린 질문으로 표시됐다.
- 첫 버전의 필수 결과와 성공 기준이 확인됐다.
- 현재 범위와 제외 범위를 사용자가 확인했다.

조건을 확인하기 전에는 작업 ID와 초기 intent를 확정하지 않는다. 로그인 방식, 기술 스택,
제외 기능처럼 사용자가 정하지 않은 사항을 임의로 결정하지 않고 질문하거나 열린 질문으로 남긴다.
신규 프로젝트에 필요한 개발환경이 없다면 기능 구현보다 환경·기본 구조 작업을 먼저 등록한다.

## 작업 분할 기준

- 한 작업은 하나의 독립적으로 검증 가능한 결과만 가진다.
- 개발환경, 인증, 핵심 기능, 부가 기능은 서로 다른 결과이므로 기본적으로 나눈다.
- 한 문장으로 인수할 수 없거나 여러 시스템을 동시에 완성해야 하면 더 작게 나눈다.
- 전체 첫 버전 범위를 하나의 작업으로 등록하지 않는다.
- 작업 구성과 순서를 사용자가 승인하기 전에는 개별 intent를 작성하지 않는다.
- 승인 전 구성안과 승인 후 작업 목록은 별도 표로 만들지 않고 같은 ROADMAP 표를 갱신한다.

## 관리

- 우선순위, 의존성, 작업 상태만 관리한다.
- 상세 요구사항·코드·테스트 로그는 작업 채팅에서 다룬다.
- 범위 변경 요청을 승인하거나 새 작업 ID를 만든다.
- 작업 채팅의 완료 보고를 확인하고 ROADMAP을 `done`으로 바꾼다.

## 작업 채팅 전달

```text
이 채팅은 AN-xxx 작업 채팅이다.
먼저 AGENTS.md, docs/workflow/WORK_CHAT.md,
docs/workflow/ROADMAP.md의 AN-xxx 행, 해당 작업 문서와
현재 변경 상태를 읽어라.
현재 단계는 [단계]다. 승인 전에는 다음 문서나 코드를 만들지 마라.
```
