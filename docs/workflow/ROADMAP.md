# Roadmap

## 프로젝트 기준

- 대상 사용자와 문제:
- 첫 버전의 필수 결과:
- 기술 구성과 개발 환경:
- 기술·아키텍처 승인: `pending`
- 개발환경 세팅·검증: `pending`
- 제외 범위:
- 성공 기준:

| ID | 결과 | 구성 승인 | 상태 | 의존성 | 인수 기준 |
| --- | --- | --- | --- | --- | --- |
| - | 아직 등록된 작업 없음 | - | - | - | intent 작성 준비 조건 확인 후 등록 |

## 작업 등록 규칙

- 총괄 채팅은 프로젝트 기준과 환경 세팅을 먼저 확정·검증한 뒤 작업 구성안을 같은 표에 `AN-xxx`로 등록한다.
- ID는 식별자일 뿐 승인을 뜻하지 않는다. 승인 전 `구성 승인`은 `pending`이다.
- 사용자 승인 후 해당 행을 `approved`로 바꾸며 별도의 승인된 작업 표를 만들지 않는다.
- 초기 intent는 `approved`이고 의존성이 없는 첫 작업에만 작성한다.
- 상태: `pending` → `building` → `review` → `done`.
- `review`: 구현과 검증은 끝났지만 사용자 인수가 남은 상태다.
- `done`: 사용자 인수가 끝난 상태다.
- 다른 기능에 영향을 주는 발견은 총괄 결정 후 의존성이나 새 작업으로 기록한다.
